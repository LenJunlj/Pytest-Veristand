# 报告中心（历史版本 + 导出）

**入口**：`http://10.10.3.88:8899` 或 `http://192.168.100.114:8899`（台架机双网段）

## 为什么需要

原先是"一次性报告"：每次 pytest 开始前 conftest 会清空 `allure-results`，结束时
`allure generate --clean` 重写 `allure-report/`，`reports/junit.xml` 也是单文件覆盖。
**上一轮的原始数据是被删除，不只是被覆盖** —— 想回看三天前那次失败，无从看起。

现在每次运行结束会自动把这一轮整份留档，页面可按项目/版本回看、导出、删除。

## 存储布局

```
reports/report_history/               ← .gitignore 内，不进 git
    deleted.log                       ← 删除审计：时间/项目/版本/类型/释放字节/操作人
    <project>/                        ← 目录名即项目 id（p2546 / c206_10 / framework）
        _history/                     ← 跨轮趋势账本（Allure2 的 history 目录，唯一写入口）
        <YYYYmmdd-HHMMSS>/            ← 版本号 = 运行开始时刻
            results/                  ← allure-results 副本（约 947KB，唯一事实源）
            junit.xml                 ← 本轮 junit 副本（约 27KB）
            meta.json                 ← 版本元数据
            report/                   ← 按需渲染出的 Allure 站点（缓存，可再生）
```

`framework` = 没有 `project.yaml` 的框架级单测（`tests/`），与 hil 项目分开计数。

## 保留策略与磁盘

| 项 | 单项目 | 可再生 | 说明 |
|---|---|---|---|
| 全量运行归档 | 50 MB | **不可再生** | `keep: 50` × 约 1MB |
| 调试运行归档 | 5 MB | **不可再生** | `debug_keep: 5`，单独成桶，不挤占 keep |
| 渲染缓存 `report/` | 约 10 MB | **可再生** | `max_generated: 3` 份 × 3.3MB |

- 全量与调试**分开计数**：调试一天能跑几十次，如果共用名额会把真正要留的全量基线挤掉。
- 缓存按"最近点开"淘汰；删掉后下次点开重新渲染 3~5 秒，**原始数据一份不丢**。
- 条数由 `config/bench.yaml` 的 `report.history` 控制：`keep` / `debug_keep` / `max_generated`。
  不设全局上限，按项目线性增长（2 个项目约 130MB）。

## 什么算"调试运行"

由命令行 argv 自动判定（`helpers/report_history.classify_kind`）：

| 判据 | 类型 |
|---|---|
| 带 `::nodeid`（单条用例） | 调试 |
| 带 `-k` / `--lf` / `--last-failed` / `--ff` / `--sw` / `--co` | 调试 |
| 以上都没有（按目录/全量跑） | 全量 |

页面上用「全量」/「调试」标签区分，不必手工维护。

## 页面功能

| 位置 | 操作 |
|---|---|
| 顶部项目标签 | 切换项目（`/?project=c206_10`） |
| `查看最新报告` | 直接打开仓库根 `allure-report/`（等价于改造前的入口） |
| 每行 `查看` | 打开该版本；首次访问会现渲染（约 3~5 秒），之后走缓存 |
| 每行 `导出ZIP` | 下载 Allure 交互包（解压后双击 `启动查看.bat`） |
| 每行 `导出HTML` | 下载单文件 HTML（双击即开，可打印 PDF） |
| 每行 `删除` | 删单个版本（二次确认） |
| `删除选中(N)` | 勾选多行批量删 |
| `删除全部调试运行` | 一键清掉该项目的调试历史，保留全量 |

**删除不可恢复**：只删 `reports/report_history` 里的版本目录，并写入 `deleted.log` 留痕。

## 页面执行（直接在页面上跑用例）

工具栏下面有一条运行栏：

```
模块  ☑左后三排加热 ☑右后三排加热 ☑功能DTC测试   ☐含 slow（耐久/长跑）   [▶ 运行]
```

- **模块勾选**：默认全选；只跑一个模块就取消其余（例如只勾 DTC 跑诊断 12 条）。
- **含 slow**：默认不勾 → 命令带 `-m "not slow"`（C206-10 约 20 分钟）。勾上则跑全部，
  包括耐久 1800s/2696s 那几条 —— **可能数小时**。
- 点击后弹确认框，列明项目/模块/是否含 slow，并提示 **DUT 会真实上电**。
- 运行中页面顶部出现状态条：状态、已用时间、`停止`、实时日志尾（每 3 秒刷新）。
- 跑完自动刷新页面，新版本落到表格顶部；状态条给出「查看本次报告」直达链接。
  （只在本页**看到过"运行中"**时刷新一次：否则任务早已结束时每次重载又满足条件，
  会变成每 2.5 秒刷新一次的无限循环 —— 2026-11-10 实际踩到并修复）

### 互斥（台架只有一台，绝不并发）

起点前做三重检查，任一不满足直接拒绝（页面弹提示，接口回 409）：

1. 已有存活任务（`reports/run_jobs/*/job.json` 里的 pid 还在）
2. 台架锁被他人持有（`C:/HIL/bench.lock`，会显示占用者 pid/机器/用户/时间）
3. 项目或模块不在 `project.yaml` 里（400，不猜路径）

命令行的 `pytest` 跑起来也会去抢同一把锁，所以"页面跑"和"人工命令行跑"天然互斥。

### 任务目录与状态

```
reports/run_jobs/<YYYYmmdd-HHMMSS>/     # 只保留最近 keep_jobs=20 个
    job.json    # 项目/模块/完整命令行/pid/状态/退出码/耗时/关联报告版本
    stdout.log  # pytest 原始输出（utf-8，页面读尾部）
    stopped.flag# 用户点过停止的哨兵（区分"被停"与"失败"）
```

| 状态 | 含义 |
|---|---|
| `running` | 正在跑 |
| `passed` | pytest 退出码 0（或被跳过的用例不影响） |
| `failed` | 退出码 1：有失败用例 |
| `error` | 退出码 4/其他：命令行用错、收集失败等（看日志） |
| `stopped` | 用户点了停止（进程树被 `taskkill /T /F` 杀掉） |
| `interrupted` | 跟踪丢失：服务重启或进程被外部结束；**用例进程可能还在跑**，日志仍在任务目录 |

- **关掉浏览器不会中断任务**：任务是独立进程，重开页面能看到进行中的状态。
- 服务重启（改代码后换 pythonw）会让运行中的任务显示 `interrupted`；此时若要确认，去
  `reports/run_jobs/<id>/stdout.log` 看，或按需 `taskkill`。
- 跑完的报告自动进历史（`conftest` 的归档钩子照常生效），所以"点了运行"就同时有执行记录和版本。

## 导出三种格式的区别

| | **单文件 Allure（默认）** | TestStand 风格 HTML | ZIP 站点包（旧） |
|---|---|---|---|
| 内容 | 完整 Allure 报告（步骤/分类/趋势/环境/执行器） | 逐条用例明细 + 失败消息 + 堆栈 | 完整 Allure 站点（多文件） |
| 打开方式 | **双击即开** | 双击即开（GBK，可打印 PDF） | 解压 → 双击 `启动查看.bat` |
| 接收方依赖 | 无 | 无 | 需要 Python（bat 起 `http.server`） |
| 体积参考 | framework 67 条 ≈ 3.5 MB | 几十 KB | ≈ 站点体积 |
| 适合 | 发给别人、存档、邮件 | 对外汇报、打印 PDF | 内部深度排查 |

生成命令：`allure generate <results> -o <out> --clean --single-file`（本机 Allure **2.29.0 已支持**；
单文件是 2.24 起的功能）。**注意**：单文件模式不产出 `history/`（[allure2#2740](https://github.com/allure-framework/allure2/issues/2740)），
所以趋势的**账本**必须由多文件站点那条链路维护（见下节）；导出时我们会把账本先灌进临时副本，
导出件里的趋势数据同样内联进去了。

ZIP 旧方案仍保留 `format=zip`（API/命令行可用，页面不再给按钮）：Allure 是前端应用，双击
`report/index.html` 会用 `file://` 去 fetch `data/*.json`，浏览器禁止 → 白屏，所以包里必须带 bat。

## 趋势（Trends / History / Retries）

Allure 2 没有服务端，趋势完全靠**上一份报告的 `history/` 目录**续上。本框架的链路：

```
本轮 allure-results/history  ←灌—  reports/report_history/<项目>/_history   （跨轮账本）
本轮 allure-report/history   —收→  reports/report_history/<项目>/_history   （唯一写入口）
```

- 账本目录用 `_history` 前缀，`list_versions` 的版本正则不会把它当成一个版本；
- 首轮 `灌入 0 个文件`，第二轮起 Trends/History/Retries 三页就有数；
- 归档版本里的 `results/history` 也会同步账本 → 单独打开某个历史版本，趋势也是完整的；
- 改 `historyId` 会断趋势：用例**改函数名**等于换了一条趋势线（参数化 id 同理）。

## 分类与元数据（categories / environment / executor）

生成前会把三份文件写进本轮 results，`allure generate` 一并吃掉：

| 文件 | 作用 | 位置 |
|---|---|---|
| `categories.json` | 失败自动归类：台架/环境异常、原文期望与时序边界、其他 | 报告 Categories 面板 |
| `environment.xml` | 台架机/用户/OS/Python/pytest/niveristand/sdf/commit/报告中心地址 | 报告 Environment 面板 |
| `executor.json` | Build 号 = 版本号，链回 `/r/<项目>/<版本>/` | 报告头部 Build + `widgets/executors.json` |

用 XML 而不是 `environment.properties`：后者走 Java Properties（ISO-8859-1），中文 sdf 路径必乱码。
分类**只做分区，不改判定**；"原文期望/时序边界"是给人对照偏差登记表看的，不是自动背书。

## 用例编号标签（.seq 追溯外键）

用例函数名本来带 dump 序号（`test_22_exit_ntc_open`），conftest 在收集阶段自动挂两个标签，
**用例文件零改动**：

- `testcase = c206_10#22` —— 报告里是用例编号，可与 `.seq` 序号 / 台账 / Excel 三方对照；
- `tag = seq:22`、`tag = module:dtc` —— 报告里可点选筛出单条。

`tests/test_report_upgrade.py::test_allure_listener_reads_our_label_marks` 是契约测试：
allure-pytest 升级若改了 mark 形状会先红，避免报告里静默少编号。

## 跑完通知（默认关闭）

`config/bench.yaml → report.notify`：填 `webhook` 并把 `enabled` 改 `true` 即生效，
企业微信/钉钉群机器人都支持（`kind: wecom|dingtalk`）。消息含结论、计数、耗时、前 5 条失败、
报告链接。**发送失败只打印一行，不改退出码**。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` `/?project=<id>` | 报告中心页 |
| GET | `/api/projects` | 项目清单（含版本数/最新版本/占用字节） |
| GET | `/api/versions?project=<id>` | 版本清单（counts / kind / argv / git / 大小 / 多个链接） |
| GET | `/api/export?project=&version=&format=single\|html\|zip` | 导出下载（默认 `single`）；`version` 可为 `latest` |
| GET | `/r/<project>/<version>/...` | 某版本的 Allure 站点；`latest` = **该项目最近一次全量运行**（见下） |
| POST | `/api/delete` | 删除；body `{"project":"c206_10","versions":[...]}` 或 `{"project":"c206_10","kind":"debug"}` 或 `{"project":"c206_10","all":true}` |
| POST | `/api/run` | 运行；body `{"project":"c206_10","modules":["dtc"],"include_slow":false}`；202 起任务，409 台架被占/已有任务 |
| POST | `/api/run/stop` | 停止当前任务（可选 body `{"job_id":...}`） |
| GET | `/api/run/status` | 当前/最近任务 + 台架占用情况 |
| GET | `/api/run/log?lines=120` | 任务日志尾部（text/plain） |

示例：

```bash
curl "http://127.0.0.1:8899/api/versions?project=c206_10"
curl -OJ "http://127.0.0.1:8899/api/export?project=c206_10&version=latest&format=html"
curl -X POST -H "Content-Type: application/json" \
     -d '{"project":"c206_10","kind":"debug"}' \
     "http://127.0.0.1:8899/api/delete"

curl -X POST -H "Content-Type: application/json" \
     -d '{"project":"c206_10","modules":["dtc"],"include_slow":false}' \
     "http://127.0.0.1:8899/api/run"
```

**导出只走 POST**：GET 会被浏览器预取/爬虫命中，破坏性操作不能用 GET 触发。
参数一律过白名单（项目 `^[A-Za-z0-9_]+$`、版本 `^{时间戳|latest}$`），非法返回 400。

> **`latest` 的统一语义 = 该项目最近一次「全量」运行**（页面 `/r/<项目>/latest/` 与导出完全一致）。
> 一份全量都没有时才退回最近一次任意运行。为什么不取"绝对最新"：调试单跑（`::nodeid` / `-k`）
> 往往只有一两条用例，2026-11-10 实测连跑 5 次单条用例把"最新报告"挤成了"1 条通过"，
> 容易被误读成整批只跑了 1 条。调试运行在版本表里照旧可见（标「调试」），点那一行就能单独看。
> 注意它**不再**直接读仓库根 `allure-report/`（那是"最后一次跑的任何东西"，可能属于别的项目）。

## pytest 侧开关

| 开关 | 作用 |
|---|---|
| 默认 | 每次运行结束自动归档（项目从用例文件所在 `project.yaml` 推出） |
| `--no-allure` | 不出 Allure，也就不归档 |
| `--no-report-history` | 出 Allure 但**不留历史**（调试垃圾太多时可临时用） |

归档在 `pytest_sessionfinish` 且 `trylast=True`：pytest 的 junitxml 插件也在该钩子写 xml，
放最后才拿得到本轮文件。归档失败只打印提示，**不改变退出码**。

## 运维

```bat
:: 重启服务（改了 serve_report.py 必须重启才生效）
taskkill /PID <8899 端口对应 PID> /F          :: netstat -ano | findstr :8899
schtasks /Run /TN AllureReport8899

:: 取消开机自启
schtasks /Delete /TN AllureReport8899 /F

:: 前台调试（有日志输出）
F:\TongYuTestScript\python.exe tools\serve_report.py
```

排障：

| 现象 | 原因/处理 |
|---|---|
| 某版本「查看」转圈很久或 503 | 正在现渲染（首次 3~5 秒）；并发点开多个版本时第二个会等锁，刷新即可 |
| 「查看」报"未找到 allure CLI / Java" | `config/bench.yaml` 的 `report.allure.bin`、`java_home` 未配对；与生成最新报告是同一依赖，最新报告能用就说明配置没问题 |
| 「导出HTML」报"没有归档 junit.xml" | 该版本归档时 junit 未写入或缺失；改用导出 ZIP |
| 页面空白/无响应 | pythonw 下 `sys.stderr=None`，任何逐请求写 stderr 的改动都会让响应变空——`Handler.log_message` 必须保持静默（已处理，勿改回） |
| 页面点「运行」立刻失败 / exit 1 | 看 `reports/run_jobs/<id>/stdout.log`：① 最常见是 **`pytest.ini` 里有中文** —— pytest 5.4.3 用系统编码（cp936）读 ini，服务拉起的子进程没有 `PYTHONUTF8`，会 `UnicodeDecodeError`；ini 必须纯 ASCII；② 台架锁被占（409）；③ 模块名不在 project.yaml（400） |
| 页面"不断刷新"/闪 | ① 先看访问日志判断是**重载**（每 2.5s 一条 `GET /`）还是**面板重绘**（每 3s `run/status`+`run/log`，属正常轮询）；② 自动刷新只在"本页看到过运行中"时触发一次；③ 运行面板按签名（id/status/exit/结束时间/版本）去重，内容没变不重建 DOM |
| 端口 8899 起不来 | 已有实例在跑（单实例设计，安静退出）；或防火墙规则被删 |
| 磁盘涨得快 | 调小 `keep` / `debug_keep`；或 `tools\export_report.py --delete --kind debug --yes` 清调试历史 |

**访问日志**（排查"谁在刷/刷多快"）：`config/bench.yaml → report.access_log: "reports/report_access.log"`，
填路径即开启、置空或 false 关闭。逐请求一行 `时间 来源IP "请求行" 状态`，超过 4MB 自动截半。
定位刷新类问题的判据：**每 2.5 秒一条 `GET /`** = 页面在自动重载；只有每 3 秒的
`GET /api/run/status` + `/api/run/log` = 正常轮询。

日志：`reports/serve_report.log`（启动、导出、删除、异常都记在这里）。

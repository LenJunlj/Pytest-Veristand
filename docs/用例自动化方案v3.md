## 0. 为什么 v2 要作废：不是工序重，是前提错

v2 的立论基础写在它自己的第 4 行：

> 前提（用户确认）：**同一人写用例+实现**；用例以 **Excel** 形式给出；**不再有存量 .seq**

第三条与事实相反——下一批用例（C206-10 等）的输入形态已被用户确认为 **.seq 存量迁移**。
这一条失效，v2 的整条工序就都错位：

| v2 环节 | 它依赖的隐含前提 | .seq 迁移下的实况 |
|---|---|---|
| 骨架生成"**零语义**" | 规范只有 Excel 自由文字，没有可解析结构 | .seq 是**精确规范**：步骤顺序、`Comparison Type: EQ`、`Limits`、`RunMode`、通道路径全在 XML 里，`seq_dump.py` 已完整取出 |
| **人工实现为主** | 人得从零决定通道/写入值/时序 | `gen_tests.py` 已把这些**实证出来**（EQ 等值判定、加热编码 0≠OFF、库序列 2s 时基），`compare_draft.py` 复核 **31/33 逐步一致、DIFF 0** |
| 对账对 **Excel 用例号** | Excel 是用例权威 | 权威是 .seq；对照物应是 **.seq 序列 ↔ test 函数** |
| Excel 作为**输入清单** | 用例先有 Excel 再有代码 | Excel 是交付物语言的载体，不是迁移的源头 |

**结论**：第九次会话实施的 A/D 批次（骨架生成 / case_matrix / smoke 快集 / fail-fast 等）方向没错、
目标错位——它服务的是"没有 .seq 的新项目"，而当前主战场恰恰是 .seq 迁移。该批次保留在
`safety/pre-rollback-20261107` + 本地 bundle，**不恢复、不删除**，其 `case_matrix` 的检查思路
（缺号/空函数/多号/漂移）被 v3 §4 的迁移台账继承，只是**数据源从 Excel 换成 dump**。

## 1. 三层事实模型（v3 的地基）

```
 .seq  ──────────►  dump JSON  ──────────►  pytest 用例
 唯一规范           可复核中间层            执行体
 只读、有版本       机械可 diff             人工迁入 tests/
                      │
                      └──────► 迁移台账（机械生成，可追溯）

 Excel  ←── 反向导出快照（可选，客户/评审要求时才做）
           **永不作为输入源**，不做双维护
```

- **规范源唯一 = .seq**。任何与代码不一致的地方，先回 .seq 查，再回台架实测查；
  两者都查不出才允许"人裁定"，且裁定必须留痕（§3 第 4 步）。
- **dump 是事实层**：所有翻译决策必须能在 dump JSON 里找到出处字段，否则视为无依据。
- **Excel 只出**：从 `allure.step` 文本 + 断言常量反向导出"用例快照"，用于评审归档；
  它永远追不上代码，**不回头修改代码**。

## 2. 迁移流水线（六步，每步都有机械保证）

| # | 步骤 | 工具 | 产物 | 机械保证（不满足即红） |
|---|---|---|---|---|
| 1 | 结构化 | `tools/seq_dump.py` | `reports/<模块>_dump.json` | 序列数 / 每步属性树完整；TestStand 硬退出防挂死 |
| 2 | 带语义生成 | `tools/gen_tests.py` | `reports/gen/<模块>/draft_all.py` + `gen_manifest.md` + 通道草稿 | **顺序严格 = dump 序**；每条语义规则必须附实证出处；名/值矛盾步骤自动标注 |
| 3 | 机械差分复核 | `tools/compare_draft.py` | 逐步骤轨迹差异（事件序列 + 睡眠序列） | 退出码 0/1；非白名单差异一律红 |
| 4 | **偏差裁定（唯一人工步）** | 人 + `KNOWN_DEVIATIONS` | 偏差条目（编号/类别/理由/实证依据） | 裁定必须同时进 ①比对器白名单 ②用例 docstring ③迁移台账；三处缺一即红 |
| 5 | 迁入 | 人工改名 `test_<dump序号>_<短名>` | `projects/<proj>/<module>/tests/test_all.py` | 一条 dump 序列 = 一个独立函数；禁止参数化合并（用户强制） |
| 6 | 台账 | `tools/migration_matrix.py`（待建，§4） | `reports/migration_matrix.md/.csv` | 缺译 / 多译 / 半成品 / 偏差未登记 自动红 |

**为什么生成器是主力而不是"骨架"**：.seq 的语义密度高（判定类型、限值、RunMode、
库序列调用模式），由人逐条重抄既慢又不可复核；生成器把语义**固化在代码里**再被差分器验证，
错一条就能定位到具体步骤。这正是 p2546 已经跑通的路径（35 条草稿 vs 手工版 33 对全量比对）。

**人工只做三件事**：复核差分结论、裁定偏差、决定 Skip 序列的去留。其余全部机械。

## 3. 偏差的三种合法类别（裁定模板）

| 类别 | 判据 | 已发生实例 |
|---|---|---|
| **等价表达** | 事件序列 + 睡眠序列归一后完全一致 | 第 33 条：手工内联 vs 生成器塌缩为 `request_heat('off')`，时序等价 |
| **合理增强** | 原文无此步，但为可判定性所必需，且不改 DUT 激励 | 第 37 条：手工版多一段"加热开启确认" |
| **实证改工况** | 原文工况在 DUT 上不成立（锁存/边界），需改参数并说明实测依据 | 第 41/42 条：6s 保持 → 3.5s（欠压 8.4V / 过压 17V + 中间自检） |

> 规则：**不允许第四类**"我觉得这样更好"。任何未归入三类的差异，要么改代码对齐原文，
> 要么补实测数据后归入"实证改工况"。

## 4. 迁移台账（本轮只定形态，不实现）

### 4.1 一行 = 一条 dump 序列

| 字段 | 取值 / 说明 |
|---|---|
| `seq_no` | dump 序号（= 函数名前缀 = 执行顺序） |
| `seq_name` | .seq 序列名 |
| `steps` | Main 组步骤数（结构性佐证） |
| `run_mode` | `Normal` / `Skip` |
| `status` | `已译` / `已译-改工况` / `xfail-存量缺陷` / `删除-用户拍板` / `待拍板-Skip` |
| `test_func` | 对应 test 函数名；删除/待拍板为空 |
| `deviation` | 空 / `等价表达` / `合理增强` / `实证改工况` / `跳过` |
| `reason` | 偏差或跳过的理由（一句话 + 实证来源） |
| `source` | .seq 文件名 + git/文件 sha，保证"这份台账对的是哪一版规范" |

### 4.2 自动判红四类

1. **缺译**：dump 有序列、`status` 为空或 `待拍板-Skip` 超期 → 红
2. **多译**：有 test 函数、dump 无对应序号 → 红
3. **半成品**：函数体只剩 TODO / `pass` / 无任何 bench 调用 → 红
4. **偏差未登记**：`compare_draft` 报非白名单差异，但台账 `deviation` 为空 → 红

### 4.3 与 Allure 的关系

- **台账 = 规范覆盖率**（"原文每条都处理了吗、为什么"）
- **Allure = 执行结果**（"迁过来的都过了吗"）
- 两者共用 `seq_no` 作外键：报告标题已带零填充序号（"01·…"），可与台账逐行对照。
- 台账入 git（
  `reports/` 被 gitignore，故基线落 `docs/migration_matrix_p2546.md`），每次迁移更新一次。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 生成器语义规则漂移（下次改代码带歪） | 每条规则必须附实证出处；`tests/test_layering.py` 已锁定通道分层等价，语义规则另在生成器头注登记 |
| 偏差裁定被跳过（代码和原文不一致但没人记） | §4.2 第 4 类判红：比对器白名单 ↔ 台账 ↔ docstring 三处对不上即报 |
| Skip 序列永久悬空 | 台账 `待拍板-Skip` 带日期，超过一个迭代即红；40min 稳定性已拍板删除并留理由 |
| 单点台架机（F 盘主副本） | 每次收尾 commit + bundle；`safety/*` tag 不动 |
| 未推送欠账累积 | 网络恢复后一次 `git push origin main`；推送失败不重试、只登记 |
| 台账自身腐化 | 台账由脚本生成，**人不手改**；理由字段例外（人写，但要短到能 review） |

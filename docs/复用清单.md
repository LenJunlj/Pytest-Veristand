## §5 待人工核对疑点（按优先级）

1. **`reset_channels` 归属错层**：bench.yaml（台架级）里放了 7 条加热模块通道。
   铺右后大屏时要拍板：a) 追加 Psn 侧通道进同一份；b) 迁到模块级（如 module.yaml），`vs` fixture 机制不用动。
2. **`test_smoke_hil.READ_PROBE` 硬编码 DI0**（p2546 机型事实写在框架级用例里）→ 建议参数化进 yaml。
3. **`bench.py` 的前提未全证实**：头注说 Setup/Cleanup"两份 .seq 完全一致"——只覆盖已 dump 的两份。
   TBOX/DTC 的 .seq 拿到后先 `seq_dump` 核对 Setup/Cleanup 是否同构，再决定是否直接继承 `BenchStimulus`。
4. **右后大屏镜像命名全部未证实**：HU_DrvSeatHeat→? / RES2→? / DO0→? / SEAT_DrvStd (993)→? / DI0→DI?
   （预期存在主驾/副驾镜像，但以 dump 为准，勿猜。）
5. **FIU 物理通道分工**：CH7/CH9（NTC 前提退出/故障恢复分工）与 CH1/CH10（输出故障）是本模块存量事实；
   右后模块是复用同一对 FIU 通道还是另一对，待 dump。**5b**：KeyState 值域建议从 bench.py 注释迁进 channels.py 值域区。
6. **`make_report.py`** 模板路径与输出文件名硬编码 p2546 → 用前手改（或参数化）。
7. **TBOX 远程加热**：请求通道、库序列时序（是否同样有 2s 内部等待）都是未知数，按 dump 重译，勿沿用 M1~M3。
8. **加热值域是否跨侧一致**：HEAT_REQ/NTC_FAULT/OUT_FAULT 的数值大概率同车型同编码，但需右后 dump 或历史报告实证后再沿用。

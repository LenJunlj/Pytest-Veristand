## 0. 你这句话改变了什么

复用清单原来的判定基线是"**通道路径都属于 TongYu_IO 模型 → 项目级，跨车型不复用**"。
你补充的事实——**台架通道定义层面许多通道本来就是复用的**——说明真实结构是：

> 通道全路径 = 「模型前缀（项目事实）」 + 「IO 分类段 + 通道名（**台架硬件事实，跨项目复用**）」 + 「功能语义/值域（模块事实）」

现在 `projects/p2546/common/channels.py` 把三种事实**混在一个文件**里，导致复用清单里大量 ❌/🔁 判定
其实是"被文件归属拖着走"，不是通道本身不可复用。分层后判定会大面积升级（§8）。

## 2. 核心思路：把一条通道拆成三段（方案的技术骨架）

以 `CH_FIU1_CH10` 为例，解剖现在的全路径：

```
Targets\Controller\Simulation Models\Models\TongYu_IO\Parameters\IO\FIU\FIU1OUT_Channel10\Value
└────────────────── ① 模型前缀 ──────────────────────┘└ ② └──── ③ 通道名 ────┘
```

| 段 | 内容 | 归属 | 复用范围 |
|---|---|---|---|
| ① 模型前缀 | `Targets\<target>\Simulation Models\Models\<模型名>\Parameters\IO` | **项目层**（模型名/目标名来自 project.yaml） | 同模型 |
| ② IO 分类段 | `FIU\`、`PowerControl\`、`HardLine IO Model\MDLDataToController\MDLSignalRouting\`、`CAN BUS\MDLSoftECUDataToBus\` | **台架↔模型接口约定**（你的通道定义表覆盖的就是这一层和③） | **同台架跨项目** |
| ③ 通道名 + 值域 | `FIU1OUT_Channel10`、`VlotageControl`（注意拼写）、CAN 信号名（`KeyState` 等整车信号其实属①′见下） | 台架硬件通道→**台架层**；功能语义/值域→**模块层** | 台架通道跨项目；功能值域看范围 |

> 细分一处：`KeyState/EngState/Crash` 的**报文名+信号名**（`BCM_VehSt1_2AB_Msg` 等）是**车型 CAN 矩阵事实**，
> 跟台架无关 → 归**项目层**；它们恰好也走 `CAN BUS\MDLSoftECUDataToBus\` 这个台架接口段，由前缀拼接体现。

分层后每层只拼自己那一段：**项目层提供①，台架层提供②③的硬件通道，模块层把功能语义挂到台架通道上。**

   ├─ common/channels.py        # 瘦身为项目层：模型前缀 + CAN 矩阵信号（KeyState/EngState/Crash/…）+ 整车值域(ENG_STATE/KeyState)
